🔥📚 Grill × Domain-Modeling 协作系统

/grilling · /grill-me · /grill-with-docs · /domain-modeling —— 4 个 skill 怎么组成一套完整的「决策追问 → 沉淀归档」流水线

mattpocock/skills 4 个 skill 全景 含 6 张图 决策树 + 速查表

🎯 一句话定位

这 4 个 skill 是一个完整的协作系统:

  • /grilling —— 苏格拉底式追问的底层引擎
  • /grill-me —— 用户的轻量入口(无副作用)
  • /grill-with-docs —— 追问 + 沉淀文档(工程推荐)
  • /domain-modeling —— 主动雕刻领域模型(术语 + ADR)

它们共同解决一个核心问题:把"想清楚"这件事,从口头对齐升级为可追溯的工程产物。

它们都来自 mattpocock/skills(GitHub 290K+ stars),Matt Pocock 称这一整套为:

"The single coolest technique in this repo."

🔧 /grilling — 底层追问引擎

/grilling
📍 角色:底层原语 📄 SKILL.md:29 行 🚀 触发:自动 📦 产出:无

一句话:苏格拉底式追问的共享引擎 —— 设计树 + frontier + 多轮追问的完整算法实现。

核心机制:Design Tree × Frontier

grilling 把"方案"建模成一棵决策树,把"追问"建模成对这棵树的 BFS 遍历。

图 2 · grilling 把方案展开为决策树,本轮问「Frontier」,下一轮重算

三段论:问 → 推荐 → 等答

图 3 · 每一轮追问的标准三段:问题 + 推荐 + 等答

关键纪律

✅ 事实自己查

需要查环境(文件、工具)时,派 sub-agent 去查,不浪费用户回合。

✅ 决策留给用户

每个决策都问用户,等回答;不替用户做价值判断。

⚠️ 不要阻塞

派 sub-agent 后不等它回来;不依赖它的问题先问,依赖它的等结果。

⚠️ Frontier 终止

frontier 为空 = 共识达成;用户确认前不要动手。

🚪 /grill-me — 手动入口(轻量版)

/grill-me
📍 角色:用户入口壳 📄 SKILL.md:9 行 🖱️ 触发:手动 📦 产出:无

一句话:grilling 的薄包装 —— 9 行 SKILL.md,只转发一次调用。

SKILL.md 全文

---
name: grill-me
description: A relentless interview to sharpen a plan or design.
disable-model-invocation: true
---

Call the Skill tool with "grilling".

整个 skill 的"逻辑"就这 5 行有效内容。把它和 /grilling 放一起对比:

🔵 /grilling

  • 完整 28 行方法论
  • 无 disable-model-invocation
  • Claude 可自动选用
  • 技术导向描述

🟢 /grill-me

  • 0 行方法论(纯转发)
  • 有 disable-model-invocation: true
  • 必须用户手动输入
  • 用户导向描述

何时用:

  • 我已经有一个方案,想让 AI 拷问一下,但不需要留任何文档
  • 临时 brainstorm、个人思考、轻量验证
  • 等价于直接说"grill me about my plan"

🏗️ /grill-with-docs — 出文档升级版

/grill-with-docs
📍 角色:工程入口 📄 SKILL.md:9 行 🖱️ 触发:手动 📦 产出:ADR + Glossary

一句话:追问 + 沉淀 —— 一次性串两个 skill,产出可追溯的工程文档。

SKILL.md 全文

---
name: grill-with-docs
description: A relentless interview to sharpen a plan or design,
             which also creates docs (ADR's and glossary) as we go.
disable-model-invocation: true
---

Call the Skill tool twice, for "grilling" and "domain-modeling".

关键差异就一个字 —— twice:

/grill-me 的正文

Call the Skill tool with "grilling".

单次,单 skill。

/grill-with-docs 的正文

Call the Skill tool twice, for "grilling" and "domain-modeling".

两次,串行 grill + domain-modeling。

产出物清单

your-project/ ├── CONTEXT.md ← 新建/更新(术语词典) ├── GLOSSARY.md ← 新建/更新(别名,功能同 CONTEXT.md) ├── docs/ │ └── adr/ │ ├── 0001-xxx.md ← 第一份 ADR(满足三条件时自动生成) │ ├── 0002-yyy.md ← 后续决策记录 │ └── ...

Matt Pocock 原话:"The single coolest technique in this repo."

何时用:

  • 项目立项、跨团队、长寿命 feature
  • 需要决策可追溯(合规、新人 onboard)
  • 需要术语统一(PM / 工程师 / 客服共享词汇)

🎨 /domain-modeling — 主动雕刻师

/domain-modeling
📍 角色:独立 skill 📄 文件:3 个 🚀 触发:自动 📦 产出:CONTEXT + ADR

一句话:边设计边主动雕刻领域模型 —— 把"术语表"和"决策记录"做成肌肉记忆。

3 个文件 = 3 种角色

~/.claude/skills/domain-modeling/ （软链接到 ~/.agents/skills/domain-modeling/） ├── SKILL.md 75 行 · 何时做 · 6 行为 · 3 条件 ├── ADR-FORMAT.md 48 行 · 怎么写 ADR └── CONTEXT-FORMAT.md 61 行 · 怎么写 CONTEXT.md

ADR 三条件过滤器

同时满足才写 ADR,任一不满足就跳过:

  1. Hard to reverse — 改起来贵
  2. Surprising without context — 不解释就奇怪
  3. Real trade-off — 有真实取舍

关键观察

✅ grilling 是底层引擎

其他 skill 都直接或间接调用它。grill-me 是"单调用转发",grill-with-docs 是"双调用串行"。

✅ domain-modeling 是独立 skill

它不是 grilling 的一部分,而是另一个 skill。可独立启用,只在 grill-with-docs 时被串入。

⚠️ 唯一非对称

grill-me → grilling 是"等价转发",无新增能力;grill-with-docs 多调一次 domain-modeling,多出文档能力。

⚠️ 路径分叉

grilling 路径产物只在内存;grill-with-docs 路径产物落文件 —— 这是唯一真正的功能差异。

🌟 4 个实战场景

场景 1:临时 brainstorm,只想拷问一下

状态:个人思考,1 个方案,无团队

推荐:/grill-me

# 触发
> /grill-me about my plan to use Redis for session storage

# AI 拷问 8-15 个问题
# 答完后 AI 给:Survived / Revised / Killed

# 不落任何文件,对话即结束

耗时:30-60 分钟

场景 2:跨团队 feature,需要术语统一 + 决策可追溯

状态:3 个团队,长寿命 feature

推荐:/grill-with-docs(作者最推荐)

# 触发
> /grill-with-docs on this RFC-002 答案溯源

# Step 1: grilling 拷问 30+ 问题
# Step 2: domain-modeling 沉淀:
#   - GLOSSARY.md 增加:citation / source / chunk / segment
#   - docs/adr/0001-citation-pointer-vs-coordinate.md
#   - 后续 /speckit-specify 引用 ADR,术语自动一致

耗时:1-2 小时

场景 3:已有术语冲突,只动术语表不动决策

状态:团队发现"Customer / Client / User"混用

推荐:/domain-modeling 独立启用

# 不需要追问,只雕刻术语
# Claude 主动:
#   1. 读现有 CONTEXT.md
#   2. 摆出冲突:你代码里 Customer / Client 都在用
#   3. 锐化为一个规范词:Customer
#   4. 更新 CONTEXT.md,_Avoid_: Client, User(本 context 中)
#   5. 不提议 ADR(无三条件)

# 不触发 grilling,纯术语维护

耗时:15-30 分钟

场景 4:让 Claude 在看到模糊需求时自动启用

状态:希望 AI 自己挑起 grill,不每次手动

推荐:让 Claude 调用 /grilling(底层原语)

# 不直接输 /grilling,而是:
> 我有一个方案,你觉得有没有漏洞?

# Claude 自动启用 /grilling(无 disable-model-invocation)
# 因为 /grill-me 和 /grill-with-docs 都禁用了自动调用
# /grilling 是唯一会自动启用的入口

耗时:取决于 AI 触发条件

🚫 反模式(什么时候不要用)

反模式后果正确做法
❌ 用 grill 探索"模糊方向" AI 不知道问什么(没东西可拷问) 先用 brainstorming 产出 RFC 草案
❌ /grill-me 装完就直接用,不写 RFC 被拷问到放弃 至少写 1 段(200+ 字)再 grill
❌ 同时启用 /grill-me 和 /grill-with-docs 对话冲突,AI 不知道用哪个 挑 1 个,推荐 /grill-with-docs
❌ /domain-modeling 自动调用 grilling 违反 skill 边界 domain-modeling 不追问,只雕刻
❌ 写 ADR 但不满足三条件 ADR 文件膨胀,失去严肃性 满足 Hard + Surprising + Trade-off 才写
❌ CONTEXT.md 混入实现细节 术语表变成代码注释 CONTEXT.md 只收"是什么",实现去 ADR
❌ grill 完不更新 RFC 回答了但方案没改 把"Revised"清单写回 RFC
❌ /grill-me 和 /grill-with-docs 期望等价 发现产物不一样就困惑 前者无文件,后者有 ADR/Glossary

📌 结论

核心要点:

  1. 4 个 skill 是一个协作系统,不是 4 个独立工具
    • /grilling 是引擎,其他 skill 是入口
    • /grill-me 是轻量入口,/grill-with-docs 是工程入口
    • /domain-modeling 是独立雕刻师,只在 grill-with-docs 时被串入
  2. 真正能"自动启用"的只有 /grilling 和 /domain-modeling
    • disable-model-invocation: true 让 grill-me 和 grill-with-docs 必须手动
    • 这是防止 AI 在不合适的时机僵化对话
  3. 唯一的功能分叉是"留不留文件"
    • grill-me / grilling → 共识在内存,会话结束即失
    • grill-with-docs / domain-modeling → 落 CONTEXT.md + ADR,可追溯
  4. 作者最推荐:/grill-with-docs(grill + 沉淀是黄金组合)
  5. domain-modeling 三条件过滤让 ADR 不泛滥 —— 这是它和"写文档就完事"流派的核心差异

下一步:

  1. 挑一个你正在做的决策,先跑 /grill-me 体验一遍
  2. 下次写 RFC,升级到 /grill-with-docs,看 ADR 自动产出
  3. 团队术语开始漂移时,单独跑 /domain-modeling 锐化
  4. 需要 fork 自定义 skill 时,把 /grilling 作为复用底座
